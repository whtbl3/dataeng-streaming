# Plan 003: Data contracts (Avro + Schema Registry, invalid events → DLQ)
From: spec.md (Approved 2026-11-18) · Approved by: project owner (2026-11-18)

## Context
Spec `specs/003-data-contracts/spec.md` (Approved 2026-11-18). Today both bronze jobs read JSON with
`json.ignore-parse-errors = false`, so one bad message stops a job (DRN-1). Nothing enforces event shape.
This feature adds Avro contracts in the Redpanda Schema Registry, a CI compatibility check, rule-based
validation, and a dead-letter path (Kafka `dlq.*` topics + `bronze.dlq_events`). Bronze tables keep
their columns.

## Two decisions to approve with this plan
1. **Compatibility mode: FULL_TRANSITIVE, not BACKWARD** (changes spec AC1 and ADR 0008).
   BACKWARD only protects a *new reader on old data*. Here the producer (simulator) upgrades while the
   running Flink job still reads with the old schema, which needs FORWARD as well. BACKWARD also allows
   removing a required field, which would break the running job and contradict AC5. FULL_TRANSITIVE =
   only add/remove fields that have defaults, checked against every earlier version.
2. **How bad messages reach the DLQ: raw-bytes source + Python UDF in the Flink SQL jobs** (new ADR 0010).
   Flink's `avro-confluent` format can only fail or crash on a bad record; it cannot route it. So each
   job reads `format = 'raw'` bytes, a Python scalar UDF decodes (Confluent wire format + registry
   writer schema + repo reader schema) and validates, and a STATEMENT SET sends good rows to bronze and
   bad rows to the DLQ sinks. Uses PyFlink, already in the stack (Python 3.11 rule, Managed Flink
   supports it). Rejected: Java UDF (no JVM code in the repo), `ignore-parse-errors` (drops silently).

## Design
**Package `contracts/`** (pure Python, unit-tested without Docker; shipped to Flink via `python.files`):
- `bounds.py`: `HCMC_BBOX`, `MAX_SPEED_KMH`, moved here from `simulator/fleet.py` (which re-imports them), so the rules and the simulator share one source.
- `wire.py`: Confluent framing (magic byte 0 + 4-byte schema id + Avro body): `frame()` / `unframe()`.
- `registry.py`: small urllib client with cache: `id_for(subject, schema)`, `schema_by_id(id)`.
- `compat.py`: offline FULL_TRANSITIVE checker for the Avro subset we use (records, primitives, nullable unions, logical types, defaults, type promotion). CLI: `python -m contracts.compat schemas/`.
- `validate.py`: GPS rules → reason codes `missing_vehicle_id`, `out_of_bbox`, `speed_out_of_range`, `event_ts_in_future` (event_ts > Kafka ingest_ts + 5 min; system time, not processing time).
- `decode.py`: `decode_gps(raw, ingest_ts)` / `decode_cdc(raw, table)` → `(row, None)` or `(None, (reason, detail, schema_id))`. Decode reasons: `not_decodable`, `unknown_schema_id`, `schema_mismatch`.
- `udf.py`: thin PyFlink wrappers (the only module importing pyflink) returning a ROW with an `error` field.

**Schemas** (`schemas/gps.pings.v1-value/v1.avsc`, `v2.avsc`): v1 = today's 6 fields (`event_ts` timestamp-millis); v2 adds `battery_pct: ["null","int"] = null` (evolution demo). The bronze job reads with the v1 reader schema; the simulator writes with the newest version.
CDC schemas are generated by Debezium from the table definitions, so they are not files in the repo. The registry protects them (FULL_TRANSITIVE per subject). A breaking DB change then fails the connector task loudly instead of breaking consumers.

**Registration** (`redpanda-init`, `rpk registry`): set FULL_TRANSITIVE on `gps.pings.v1-value` and `cdc.public.{depots,vans,orders}-value`, register `v1` then `v2` in order (idempotent), create the `dlq.<source topic>` topics (3 partitions, 7 days). The producer never auto-registers: it fails fast if its schema is missing.

**Producer** (`simulator/producer.py`): `encode()` writes framed Avro with the id looked up at start. CLI gains `--invalid-rate` (default 0). A seeded share of pings becomes one of 5 labelled kinds (4 rule breaks + raw non-Avro bytes); `produce_all` returns counts per kind (AC7). A future-time ping is set relative to wall clock, so the rule fires in history mode too.

**CDC** (`infra/local/connect/`): new `Dockerfile` (Debezium 3.6.3 + converter zip). `ct-orders.json` value converter → `io.confluent.connect.avro.AvroConverter` (`value.converter.schema.registry.url`, `auto.register.schemas=true`). Keys stay JSON (no consumer reads them).

**Flink jobs:**
- Image: Python 3.11 venv (via a pinned `uv` binary), `apache-flink` + `fastavro`; `contracts/` mounted read-only.
- `_init_catalog.sql`: `python.executable`, `python.files`, `CREATE TEMPORARY FUNCTION … LANGUAGE PYTHON`.
- Each source becomes `raw` bytes + metadata.
  - Statement set `bronze_gps`: bronze (`error IS NULL`), `bronze.dlq_events`, and Kafka `dlq.gps.pings.v1`.
  - `bronze_cdc` does the same per table.
- Kafka DLQ sink: `raw` value, headers `reason` / `source_topic` / `partition` / `offset`, `exactly-once` with a transactional id prefix and `transaction.timeout.ms = 900000` (Redpanda's max).
- Bronze-layer watermarks are dropped: nothing in bronze uses them, and silver adds them in feature 4.
- Bronze columns and values are unchanged.

**DLQ table** (`trino/init/003_dlq.sql`): `bronze.dlq_events(source_topic, kafka_partition, kafka_offset, ingest_ts, reason, detail, schema_id, raw_value VARBINARY)`, partitioned by `day(ingest_ts)`.

**Ops and CI:**
- `make dlq-status`: rejects per source and reason, via Trino.
- `make check` runs `python -m contracts.compat schemas/` (AC5, no Docker).
- Taskmanager memory goes from 1536m to 2g (Python worker per job).

## Departures from the approved plan (found while building)
- **One decode per message.** With separate projections per sink, `EXPLAIN` showed three `PythonCalc` nodes, so each message was decoded three times. The UDF now also takes the Kafka metadata and returns it inside its ROW, together with `raw_value` for rejects. The sinks read only that ROW, so the planner reuses one `PythonCalc` (`reuse_id=1`). This was the planned fallback, implemented as a scalar UDF instead of a UDTF.
- **Catalog: one JDBC connection** (`CATALOG_CLIENTS=1`). With the fixture's default pool of 2, SQLite answered `SQLITE_BUSY_SNAPSHOT` and the REST catalog returned HTTP 500 on most commits, for the unchanged CDC job too. The failure only appeared once five Flink committers and Trino shared the catalog. Requests now run one at a time. The AWS side (Glue) is not affected.
- **Repo rules that this feature bends** (`.claude/rules/flink.md`), to be confirmed by the owner:
  - "Every source declares a WATERMARK on `event_ts`": the bronze sources read raw bytes, so there is no `event_ts` column before decoding. Bronze is append-only and uses no event time; silver (feature 4) declares the watermark.
  - "Pure Python logic lives in `flink/udf/`": the rules live in `contracts/` because the simulator (producer side) uses the same code.

## Order of work
1. Pure Python first: `bounds` / `wire` / `compat` / `validate` with tests; schemas v1/v2 plus the CI compat step.
2. Producer Avro encoding and invalid-event injection (tests with a fake registry); `make check` green.
3. Flink image with PyFlink. Smoke test: a trivial Python UDF in `sql-client`; check `EXPLAIN` shows one decode per row (sub-plan reuse).
4. GPS path end to end: registration, producer, `bronze_gps` + DLQ sinks; spec 001 e2e tests still green.
5. CDC path: Connect image + converter, capture the orders schema fixture, `decode_cdc` + tests, `bronze_cdc`; spec 002 e2e tests still green.
6. E2E tests for AC1, AC3, AC4, AC6 and AC8; memory (AC9); `make dlq-status`.
7. Docs and ADRs, then `make check`, `make e2e` and `make e2e-restart`; spec Implemented; PR.

## Risks and rollback
- **Python UDF throughput** (the 100M backfill target ≥ 20k ev/s is measured in feature 5). Live load is about 40 ev/s, which is fine. Mitigations if it is too slow: bundle tuning, then a vectorized (pandas) UDF. Recorded in ADR 0010.
- **Decode evaluated once per sink** if the planner does not reuse the decode sub-plan. Checked with `EXPLAIN` in step 3. Fallback: one UDTF emitting `(row, error)`.
- **TIMESTAMP_LTZ results from a Python UDF** and Debezium's `ZonedTimestamp` strings may need explicit casts. Checked in step 3.
- **The Confluent converter on Kafka 4.3 Connect.** Fallback: converter 8.3.3.
- **Kafka exactly-once DLQ sink vs Redpanda transactions.** Fallback: at-least-once for the topic only (the Iceberg DLQ stays exactly-once; AC3 counts the Iceberg table).
- **Memory and build time:** the image grows (PyFlink pulls Beam, pyarrow and pandas). Checked by AC9 and the "fresh `make up` < 10 min" goal.
- **Breaking local data:** JSON already in topics and the old checkpoints cannot be read. Run `make clean` once (stated in the spec).
- **Rollback:** revert the branch and `make clean`. Nothing outside this repo's local stack changes.
