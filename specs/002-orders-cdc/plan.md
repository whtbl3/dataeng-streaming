# Plan 002: Orders with CDC (Postgres → Debezium → Kafka → Iceberg bronze)
From: spec.md (Approved 2026-11-18) · Approved by: project owner (2026-11-18)

## Context
Spec `specs/002-orders-cdc/spec.md` (Approved 2026-11-18). Today the pipeline only knows where vans are.
This feature adds:
- an order database (depots, vans, orders);
- **one coupled day simulator** that drives both the order lifecycle and the vans' GPS (vans follow their stops, replacing the random walk from 001);
- Debezium CDC into Kafka;
- a Flink job that appends every change to per-table bronze changelog tables.

On approval this becomes `specs/002-orders-cdc/plan.md` + `tasks.md`.

## Design
**Simulator (pure, deterministic, seeded). Layout:**
- `simulator/world.py`: 4 depots (fixed HCMC coordinates) and 200 vans (`VAN-0001…`, 50 per depot, round-robin).
  It is the single source of truth for the seed data.
- `simulator/day.py`: `simulate_day(seed, local_date, vans, orders_per_day, late_rate, fail_rate, prefix)`. It precomputes the whole day, then yields time-ordered events.

**How a day is simulated:**
- **Shifts:** two waves per van, departing 08:00 and 14:00 Asia/Ho_Chi_Minh (≈ 12 stops each).
- **Orders:** created during the hours before their wave and assigned 30 minutes before departure.
- **Stops:** destinations are random within 6 km of the depot (inside the bbox). Vans drive straight lines at 20–40 km/h. About 10% of hops are traffic jams (speed × 0.2–0.4). Each stop has a dwell of 2–6 minutes at speed 0. Vans return to the depot after each wave.
- **Outcomes:** at the end of the dwell the order turns `delivered`, or `failed` for a sampled 2%.
- **Promised windows:** windows are 2 hours long and are set from the precomputed arrival.
  - For a sampled `late_rate` share of delivered orders: `window_end = arrival − U(5,40) min`.
  - For the others: `window_end = arrival + U(10,90) min`.
  - In both cases `window_start ≥ created_at + 1 h`.
  - This gives exact, configurable rates (AC4). In feature 6, the GPS-based ETA will show late orders crossing their window early, which is what the alerts need.
- **GPS:** pings every 5 s for all vans for 24 h (parked at the depot with speed 0 outside waves). Positions are interpolated along the segments, with ≤ 10 m jitter. At the delivery or failure time the van sits at the stop (AC3).

**Modes:**
- **history:** event window `[now − H, now]`. Order events before the window are applied first without their pings (catch-up), so the database is consistent.
- **realtime:** catch up the orders up to now, then send each event at its time.
- Both modes handle the local dates the window covers (it may span two days).

**Sinks:**
- `simulator/orders_db.py` writes one transaction per order event with psycopg. Inserts use `ON CONFLICT DO NOTHING`, and updates use `WHERE status <> new`. Re-runs are therefore idempotent, and the writer returns the number of rows actually changed (= N for AC5).
- GPS keeps using `simulator/producer.py`.

**CLI:** `python -m simulator day [--vans 20 --orders-per-day 500] [--history-hours 24 | --realtime] [--no-db] [--no-gps] [--prefix ORD]`.
- `python -m simulator seed-sql` prints the seed SQL.
- The old random-walk command is removed.

**Database (`infra/local/postgres/`):**
- `init/001_schema.sql`:
  - `depots`, `vans`, and `orders` (status `CHECK`, lifecycle timestamps, promised window, `updated_at`).
  - `REPLICA IDENTITY FULL` on `orders`.
  - Publication `ct_cdc` for the 3 tables.
- `init/002_seed.sql`: generated by `seed-sql` and committed. A unit test fails if it drifts from `world.py`.

**CDC:**
- `connect` service (profile `cdc`): Kafka Connect, internal topics on Redpanda, `-Xmx512m`.
- `connect-init` registers the connector with an idempotent `PUT /connectors/ct-orders/config` from `infra/local/connect/ct-orders.json`. Settings:
  - `pgoutput`, slot `ct_cdc_slot`, publication `ct_cdc` (autocreate disabled), `topic.prefix=cdc`, `snapshot.mode=initial`;
  - JSON converters without schemas, `decimal.handling.mode=double`, `heartbeat.interval.ms=10000` (keeps the slot advancing);
  - `tombstones.on.delete=false`.
- `redpanda-init` pre-creates `cdc.public.{depots,vans,orders}` (3 partitions, keyed by primary key) so Flink sources never see a missing topic.

**Bronze:**
- `trino/init/002_bronze_cdc.sql` creates `bronze.depots_cdc`, `bronze.vans_cdc` and `bronze.orders_cdc`, each with these columns:
  - `op` (c/u/d/r)
  - `before ROW(…)` and `after ROW(…)` (typed)
  - `source_lsn`, `source_txid`
  - `commit_ts` (source.ts_ms) and `capture_ts` (envelope ts_ms)
  - `kafka_partition`, `kafka_offset`, `ingest_ts`
- `orders_cdc` is partitioned by `day(commit_ts)`.
- `flink/jobs/bronze_cdc.sql`: one job (`bronze_cdc`) with a STATEMENT SET of 3 Kafka sources → 3 Iceberg sinks.
  - It reads the Debezium envelope with the plain `json` format, so the changelog stays **append-only raw** (no `debezium-json` changelog semantics in bronze).
  - The WATERMARK is on `commit_ts`.

**Ops:**
- `make up` enables `PROFILES ?= cdc`.
- `make cdc-status` shows the connector state plus slot lag (`pg_wal_lsn_diff` from `pg_replication_slots`).
- `make psql` opens a shell on the order database.
- Flink `taskmanager.numberOfTaskSlots` goes from 2 to 4 (2 jobs now; room for 003/004).

## Risks and rollback
- **WAL growth from an inactive slot** (ADR 0004). Mitigation: `max_slot_wal_keep_size=1GB`, a heartbeat to keep the slot advancing, lag shown by `make cdc-status`; `make clean` drops the volume.
- **Debezium at-least-once.** A crash (not a graceful stop) can replay changes. AC7 covers the graceful stop; duplicates stay identifiable by `source_lsn` and are removed in silver (feature 4).
- **The timestamptz/ROW mapping** (Debezium ISO strings → Flink `TIMESTAMP_LTZ` → Iceberg struct fields) may need explicit `CAST`s; it is checked in the smoke test before the e2e tests.
- **Simulator rewrite breaks 001 behaviour.** The 001 e2e tests are kept; they produce pings directly through `produce_all`, so they stay valid.
- **Memory:** Connect adds ~0.7 GB (expected total ~3.3 GB, AC9 < 6 GB).
- **Flink slots:** 2 jobs × parallelism 1; slots raised to 4.
- **Rollback:** everything is behind compose profile `cdc` and new files. Revert the branch; `make clean` removes the Postgres/Connect state.

## Departures from the plan (recorded during build)
- Postgres host port is **15432** (5432 was taken on the dev machine); `ORDERS_DSN` defaults to it.
- `window_start = max(window_end − 2 h, created_at + 15 min)` instead of `+ 1 h`: with `+ 1 h`
  some late orders of the first wave would get an empty window. The spec only requires the
  window to start after creation.
- The Iceberg catalog `CREATE CATALOG` moved to `flink/jobs/_init_catalog.sql`, shared by all
  jobs through `sql-client -i`.
- The connector is registered by `infra/local/connect/register.sh` (mounted into `connect-init`);
  credentials are read via Kafka Connect's `EnvVarConfigProvider` (`${env:...}`), not stored in JSON.
- GPS jitter is a counter-based hash of (seed, van, tick), so pings for any time window equal
  the full-day pings for the same ticks (needed for history windows and later backfill).
- `test_seed_captured_once_as_snapshot` waits for the first Iceberg commit after a cold start
  (it failed once when run immediately after `make up`).
- Measured (2026-11-18, laptop, WSL 10 GB / 8 vCPU): cold `make up` with images cached 60 s;
  stack memory ≈ 3.1 GiB (Trino 1.18, TM 0.55, Connect 0.52 GiB); e2e 10 passed, restart test passed.
