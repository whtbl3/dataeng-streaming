# 0008: Avro + Schema Registry as data contracts
Date: 2026-11-17 · Updated: 2026-11-18 (spec 003) · Status: Final locally; Proposed for the AWS side (confirm in feature 10)

## Context
Producers (the simulator, Debezium) and consumers (Flink) must agree on event shape, and
schema changes must not break running jobs.

## Decision
Avro schemas are the contract, registered in the Redpanda Schema Registry (Confluent API) and
written in the Confluent wire format.

- **Compatibility: FULL_TRANSITIVE** on every value subject. BACKWARD alone only protects a new
  reader on old data. Here the producer usually upgrades first while the running Flink job still
  reads with the old schema, which also needs FORWARD. BACKWARD would also allow removing a
  required field the job depends on. FULL_TRANSITIVE means: only add or remove fields that have
  a default, checked against every earlier version.
- **GPS schemas live in git** (`schemas/<subject>/v1.avsc`, `v2.avsc`, ...), are registered by
  `redpanda-init`, and are checked offline in CI (`python -m contracts.compat schemas/`). The
  producer only looks up its schema id; it never auto-registers.
- **CDC schemas are generated by Debezium** from the table definitions (Confluent Avro converter,
  auto-registration on). The registry's FULL_TRANSITIVE mode protects them: a breaking table
  change fails the connector task loudly, while the replication slot keeps the WAL.
- **A breaking change gets a new topic** (`.v2`), not a forced registry change.
- Bad messages are dead-lettered by the consumer (ADR 0010).
- On AWS, use AWS Glue Schema Registry (Glue converter in MSK Connect; the decode UDF switches
  its registry client by config).

## Options considered
- **Avro + registry (chosen):** compact, typed, and evolution rules are enforced.
- **JSON + JSON Schema checked only in CI:** simpler, but no runtime enforcement and larger messages.
- **Protobuf:** fine too, but less native in Flink SQL and Debezium.

## Consequences
- \+ A GPS ping shrinks from 133 bytes of JSON to 52 bytes of Avro (v1; 55 bytes with the v2
  field), including the 5-byte wire header. Measured on the same ping, before Kafka compression.
- − Different serde formats locally (Confluent wire format) and on AWS (Glue). If this proves
  too costly in feature 10, fall back to a self-hosted Confluent-compatible registry on Fargate.
  That is why the AWS side is still Proposed.
